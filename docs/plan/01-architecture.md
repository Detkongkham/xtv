# 01 — ສະຖາປັດຕະຍະກຳ ແລະ ຫຼັກການ

## 1. ເປົ້າໝາຍ
1. **ໄວເປັນອັນດັບໜຶ່ງ.** ຜູ້ເຂົ້າຊົມຕ້ອງໄດ້ໜ້າເວັບໄວທີ່ສຸດເທົ່າທີ່ shared hosting ເຮັດໄດ້.
2. **ໃຊ້ງານໄດ້ແທ້.** ພະນັກງານທີ່ບໍ່ແມ່ນໂປຣແກຣມເມີ ແກ້ເນື້ອຫາ 4 ພາສາໄດ້ເອງ, ແລະ ຂໍ້ຄວາມຈາກລູກຄ້າໄປຮອດທີມຂາຍທຸກຄັ້ງ.
3. **ປອດໄພ ແລະ ດູແລງ່າຍ.** ຈຸດທີ່ຄົນນອກແຕະ PHP ໄດ້ມີໜ້ອຍທີ່ສຸດ. ໂຄດນ້ອຍ, ບໍ່ມີ framework ໃຫຍ່.

## 2. ຫຼັກການຫຼັກ: Static publish
ໜ້າເວັບສາທາລະນະທຸກໜ້າເປັນ **ໄຟລ໌ HTML ສຳເລັດຮູບ**. PHP ແລະ MySQL ໃຊ້ສະເພາະໃນ admin, ຕອນເຜີຍແຜ່ ແລະ ຕອນຮັບຟອມຕິດຕໍ່.

```
                ┌──────────────── ພະນັກງານ ────────────────┐
                │                                          │
                ▼                                          │
        /admin/ (PHP)  ──ບັນທຶກ──▶  MySQL                  │
                │                    │                     │
          ກົດ "ເຜີຍແຜ່"              │ ອ່ານຂໍ້ມູນ             │
                ▼                    ▼                     │
        Publisher (PHP) ──ສ້າງ──▶ lo/ en/ th/ zh/*.html     │
                                 sitemap.xml               │
                                     │                     │
                ┌────────────────────┘                     │
                ▼                                          │
  ຜູ້ເຂົ້າຊົມ ◀── Apache ສົ່ງໄຟລ໌ HTML/CSS/JS/ຮູບ ໂດຍກົງ      │
      │                                                    │
      └── ສົ່ງຟອມຕິດຕໍ່ ──▶ /api/contact.php ──▶ MySQL + ອີເມວ ─┘
```

### ເປັນຫຍັງຈຶ່ງເລືອກວິທີນີ້
| ທາງເລືອກ | ຄວາມໄວໜ້າເວັບ | ຄວາມສ່ຽງ | ໝາຍເຫດ |
|---|---|---|---|
| **Static publish (ເລືອກ)** | ໄວທີ່ສຸດ: Apache ສົ່ງໄຟລ໌ໂດຍກົງ | ຕ່ຳ: ຜູ້ເຂົ້າຊົມບໍ່ແຕະ PHP ຍົກເວັ້ນຟອມ | ເນື້ອຫາໃໝ່ຂຶ້ນເວັບເມື່ອກົດເຜີຍແຜ່ |
| PHP ດຶງ DB ທຸກຄັ້ງທີ່ເປີດໜ້າ | ຊ້າກວ່າ: ທຸກໜ້າຕ້ອງແລ່ນ PHP ແລະ query | ກາງ | Server ນີ້ບໍ່ໄດ້ເປີດ PHP-FPM, ຈຶ່ງຊ້າຂຶ້ນອີກ |
| WordPress | ຊ້າທີ່ສຸດ | ສູງ: plugin ແລະ ການອັບເດດ | ໜັກເກີນໄປສຳລັບເວັບບໍລິສັດນີ້ |

### ຜົນດີເພີ່ມເຕີມ
- ຖ້າ MySQL ລົ້ມ, ໜ້າເວັບຍັງເປີດໄດ້ປົກກະຕິ.
- ເອົາ CDN ເຊັ່ນ Cloudflare ມາໃສ່ທາງໜ້າໄດ້ງ່າຍ, ເພາະທຸກໜ້າເປັນໄຟລ໌ຄົງທີ່.
- URL ຄືເກົ່າ (`/lo/product-ct-scan.html`). ລິ້ງທີ່ແຊຣ໌ໄປແລ້ວຈຶ່ງບໍ່ເສຍ.

## 3. ສ່ວນປະກອບຂອງລະບົບ

| ສ່ວນ | ໜ້າທີ່ | ເທັກໂນໂລຢີ | ຢູ່ໃສ |
|---|---|---|---|
| ໜ້າເວັບສາທາລະນະ | 69 ໜ້າ × 4 ພາສາ | HTML, CSS, JS ທຳມະດາ | `public/lo/`, `en/`, `th/`, `zh/`, `public/assets/` |
| Contact API | ຮັບຟອມ, ກວດ, ກັນ spam, ບັນທຶກ, ສົ່ງອີເມວ | PHP 8.3 | `public/api/contact.php` (ໄຟລ໌ນ້ອຍທີ່ເອີ້ນໂຄດໃນ `app/`) |
| Admin | ຈັດການເນື້ອຫາ, ກ່ອງຂໍ້ຄວາມ, ຜູ້ໃຊ້, ການຕັ້ງຄ່າ | PHP 8.3 render ຝັ່ງ server + JS ເລັກນ້ອຍ | `public/admin/` (ໄຟລ໌ນ້ອຍທີ່ເອີ້ນໂຄດໃນ `app/`) |
| Publisher | ສ້າງ HTML ທັງໝົດຈາກ DB | PHP 8.3 | `app/src/Publish/` |
| ໂຄດ app | ໂຄດທັງໝົດ, config, log, backup | PHP | `/home/xtklaos/xtk/app/` **ນອກ docroot** (docroot = `/home/xtklaos/xtk/public`) |
| ຖານຂໍ້ມູນ | ເນື້ອຫາ, ຂໍ້ຄວາມ, ຜູ້ໃຊ້ | MySQL 8.0, `utf8mb4` | localhost |
| ອີເມວ | ແຈ້ງເຕືອນທີມງານ ແລະ ຕອບກັບລູກຄ້າ | SMTP ຂອງ cPanel ຜ່ານ PHPMailer | mailbox `noreply@xtklaos.com` |
| Cron | Backup ທຸກມື້, ລຶບ log ເກົ່າ | PHP CLI | cPanel Cron Jobs |

ໂຄດທັງໝົດຢູ່ **ນອກ docroot**. ໃນ docroot ມີແຕ່ໄຟລ໌ PHP ນ້ອຍໆທີ່ `require` ໂຄດຈາກ `app/`. ລາຍລະອຽດໃນ [05-folder-structure.md](05-folder-structure.md). ສະນັ້ນເຖິງ Apache ຕັ້ງຄ່າຜິດ, ຄົນນອກກໍອ່ານໂຄດ ຫຼື config ບໍ່ໄດ້.

## 4. ການໄຫຼຂອງວຽກຫຼັກ

### 4.1 ລູກຄ້າສົ່ງຟອມຕິດຕໍ່
1. Browser ສົ່ງ `POST /api/contact.php` (ໃຊ້ `fetch`. ຖ້າບໍ່ມີ JS ກໍສົ່ງຟອມແບບທຳມະດາ).
2. ກວດ honeypot, ເວລາຕື່ມຟອມ ແລະ ຈຳນວນການສົ່ງຕໍ່ IP.
3. ກວດຂໍ້ມູນທຸກຊ່ອງ. ຖ້າຜິດ ສົ່ງ error ກັບໄປເປັນລາຍຊ່ອງ.
4. ບັນທຶກລົງຕາຕະລາງ `messages`.
5. ສົ່ງອີເມວແຈ້ງທີມງານ ແລະ ອີເມວຕອບກັບລູກຄ້າເປັນພາສາທີ່ລູກຄ້າໃຊ້. ຖ້າສົ່ງອີເມວບໍ່ສຳເລັດ ຂໍ້ຄວາມກໍຍັງຢູ່ໃນ DB ແລະ ຂຶ້ນໃນ admin.
6. ຕອບ `200 {"ok":true}` ແລ້ວໜ້າເວັບສະແດງຂໍ້ຄວາມສຳເລັດ.

### 4.2 ພະນັກງານແກ້ເນື້ອຫາ
1. ເຂົ້າ `/admin/` ແລ້ວແກ້ສິນຄ້າ, ຂ່າວ ແລະ ອື່ນໆ. ລະບົບບັນທຶກລົງ DB ທັນທີ, ແຕ່ໜ້າເວັບຍັງບໍ່ປ່ຽນ.
2. Dashboard ສະແດງວ່າ "ມີການປ່ຽນແປງທີ່ຍັງບໍ່ເຜີຍແຜ່".
3. ກົດ **ເຜີຍແຜ່**. Publisher ສ້າງ HTML ທັງ 4 ພາສາໃສ່ໂຟນເດີຊົ່ວຄາວ, ກວດຜົນ, ແລ້ວສັບປ່ຽນເຂົ້າ docroot ໃນຄັ້ງດຽວ.
4. ບັນທຶກຜົນໃນ `publish_log`. ທັງໝົດໃຊ້ເວລາປະມານ 1–5 ວິນາທີ ສຳລັບ ~276 ໜ້າ.

### ສິ່ງທີ່ຍັງຕ້ອງກວດ (P0-A1, ກວດໃນເຟດ S)

- ມີ `composer` ແລະ `git` ໃນ server ຫຼື ບໍ່. ຖ້າບໍ່ມີ ໃຫ້ອັບ `vendor/` ຈາກເຄື່ອງ.

## 6. ກົດທີ່ທຸກຄົນຕ້ອງເຮັດຕາມ
1. **ຫ້າມແກ້ໄຟລ໌ HTML ໃນ `lo/ en/ th/ zh/` ດ້ວຍມື.** ໄຟລ໌ເຫຼົ່ານີ້ຖືກສ້າງໃໝ່ທຸກຄັ້ງທີ່ເຜີຍແຜ່.
2. **ຫ້າມ commit ລະຫັດຜ່ານ.** ຄ່າລັບຢູ່ໃນ `config/config.php` ຂອງ server ເທົ່ານັ້ນ. ໃນ repo ມີແຕ່ `config.example.php`.
3. **ທຸກ query ໃຊ້ prepared statement.** ທຸກຂໍ້ຄວາມທີ່ສະແດງຜົນຕ້ອງ escape.
4. **ໜ້າເວັບຕ້ອງອ່ານໄດ້ເຖິງບໍ່ມີ JS.** JS ເປັນພຽງສ່ວນເສີມ.
5. **ອອກແບບຕາມ [design.md](../../design.md).** ຫ້າມເພີ່ມສີ, ຟອນ ຫຼື ໄລຍະຫ່າງນອກ tokens.
